# Healthcare Claims Analytics

Analysis of **synthetic** prescription (Rx) and medical (Dx) claims data with
Python, pandas, matplotlib, and SQL (SQLite) — built to demonstrate an
end-to-end claims analytics workflow: data generation → validation/cleaning →
analysis → SQL equivalents → charts and findings.

> **⚠️ Synthetic data disclaimer:** Every row in this project is generated by
> `generate_data.py` with a seeded random number generator. Drug names, code
> formats, pharmacies, and cost patterns are modeled after real-world claims,
> but **no real patient, member, or claim data is used anywhere**, and member
> IDs are fictional. Do not use this data for any real decision-making.

## Key findings (from the included synthetic dataset)

- **Total paid:** $7,156,804 across 1,199 members ($4,230,151 medical + $2,926,653 pharmacy).
- **Specialty drugs dominate pharmacy spend:** Humira alone is $1,316,571 — **45.0% of all
  pharmacy spend**. The top 5 drugs (all brand biologics/GLP-1s) total ~$2.73M, ~93% of Rx spend.
- **Brand vs generic:** brand claims average **$1,566.22** per claim vs **$19.00** for generics
  (~82×), while generics are the majority of claim volume (2,359 of 4,199 Rx claims).
- **PMPM trend:** cost per member per month rose from **$490.02 (Jan 2025)** to
  **$541.82 (Dec 2025)**, +10.6% over the year.
- **Most common diagnosis:** Essential hypertension — 950 claims, 15.8% of medical claims.
  Circulatory is the largest diagnosis category by spend ($1,253,119).
- **Spend concentration:** the top 5% of members by spend account for **17.4%** of total paid.

## How to run

```bash
pip install -r requirements.txt
python generate_data.py     # -> data/pharmacy_claims.csv, data/medical_claims.csv
python clean_validate.py    # -> data/*_clean.csv, claims.db (SQLite)
python analysis.py          # -> prints insights, saves charts/ PNGs
sqlite3 claims.db < queries.sql   # (or run the queries in any SQLite client)
```

## Schema

**pharmacy_claims** — one row per Rx claim:
`claim_id, member_id, age_band, service_date, ndc (NDC-like drug code), drug_name,
is_generic, quantity, days_supply, paid_amount, pharmacy`

**medical_claims** — one row per Dx claim:
`claim_id, member_id, age_band, service_date, icd10 (ICD-10-like diagnosis code),
diagnosis, category, procedure_code (CPT-like), provider_specialty, paid_amount`

## Project structure

```
generate_data.py    Synthetic Rx + Dx claims generator (seeded RNG, 2025 dates)
clean_validate.py   Schema checks, negative-amount & duplicate-claim removal, SQLite load
analysis.py         Headline metrics + 3 charts (pandas/matplotlib)
queries.sql         The same headline metrics in SQL (CTEs, window functions)
data/               Generated CSVs (raw + cleaned)
charts/             monthly_spend_trend.png, top_drugs_by_spend.png, diagnosis_category_share.png
ANALYSIS.md         Findings summary with computed numbers
```

## Notes

The generator intentionally injects a small number of data-quality issues
(one negative paid amount, one duplicated claim) so `clean_validate.py` has
real defects to detect and remove — mirroring production claims feeds.
